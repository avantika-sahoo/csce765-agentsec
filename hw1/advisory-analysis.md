One current OpenClaw security advisory is GHSA-9f86-pvv5-rxfw, which was published in the week of September 7, 2026. It affects versions below 2026.8.1 and was patched in version 2026.8.1. This security advisory highlights that escaped newlines could confuse exec allowlist parsing. Newline parsing is the process of reading text or data and finding the end-of-line control characters to split the information into individual lines. Exec allowlist parsing is a mechanism that OpenClaw uses to inspect command strings before allowing them to execute. This advisory informs that escaped newlines could confuse the exec allowlist parsing and potentially allow unauthorized commands to run.

The vulnerable component in this security advisory is the exec policy engine, which is responsible for evaluating actions, commands, and tool calls before allowing them to run. In this case, the exec policy engine is unable to detect shell word sequences or additional commands if they are hidden by newline parsing.

The attacker-controlled input in this advisory is the model input, which is the information that OpenClaw processes. Through the model input, an attacker could include a hidden command using an escaped newline, which would confuse the exec policy engine, bypass the security, and execute.

One of the preconditions needed for this exploitation is that the exec policy engine must be in use so that the data is processed. The attacker would need to include their shell word sequence or command in the data being processed by hiding it with escaped newlines. The data would also need to somehow be read into the exec policy engine, which could be done by user input or from the model reading an external source. The advisory states that the agent would require a certain exec host, sandbox mode, process permissions, and commands.

The advisory lists that one of the root causes is the improper neutralization of special elements used in an OS command. In other words, OpenClaw does not properly handle special elements that could modify the intended OS command. The second root cause listed is that OpenClaw does not properly perform its authorization check when an action is attempted.   

The impact of this vulnerability is that the model could run an additional command that it is not authorized to. The command could cause the system to impact components beyond its security scope. There could be a loss of data confidentiality if the command gives data to an unauthorized user. An unauthorized user may use this vulnerability to modify sensitive data. Additionally, an unauthorized user may cause the data to become unavailable to the proper parties.

On the developer end, the fix for the issue would be to disable exec for lower-trust agents and require review of the command outside of the parser path. Additionally, developers could sanitize the inputs to handle the newlines before the agent runs or parses the data. On the user end, the fix is to upgrade OpenClaw to version 2026.8.1 or later.

A regression test to perform would be to provide the model with data that contains an escaped newline followed by a hidden command. The data should go through the full execution path so that the updated patch can be tested for the vulnerability. When done executing, the final result should be evaluated by checking if the hidden command was executed.

In this scenario, prompt injection would be merely helpful. An attacker may utilize prompt injection to create the malicious command, but the vulnerability in this advisory concerns a parser flaw. An attacker could have their own malicious command and hide it in the data to exploit the parser flaw, so prompt injection is not necessary.
